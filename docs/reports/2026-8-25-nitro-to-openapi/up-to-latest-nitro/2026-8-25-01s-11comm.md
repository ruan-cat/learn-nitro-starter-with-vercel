## 4. 危险点聚焦（最高优先 3 项）

### 4.1 169 路由全量依赖 alpha 子路径导出（🔴 高）

所有 handler 依赖 `nitro/h3`、`nitro/runtime-config` 子路径导出和 `defineHandler`。这些子路径导出在 beta 中的名称、签名、模块位置若有任何调整，**169 个文件可能整体编译失败**。`useRuntimeConfig` 从 `nitro/runtime-config` 导入也是敏感点——该子路径是否保留是本次升级的首要确认项。

- 前置动作：升级前先对 alpha.2 与 260610-beta 的导出表做 diff，锁定受影响文件清单。
- 好在：全仓库统一经 `nitro/h3` 重导出，**没有散落的直接依赖**，迁移面可收敛到重导出层。

### 4.2 CF env 读取链路（🔴 高）

`event.req.runtime.cloudflare.env` 共 3 处使用（`env.ts` / `env-inspector` / `auth`），是 DB URL 解析的唯一入口。当前写法已经是 beta 新形态（260311 变更后），**保持概率高但不可假设**：若 beta 再次调整 `req.runtime` 结构，CF preset 下数据库连接会静默失效（构建期可能不报错）。

- 回归手段：CF preset 构建通过后，运行时请求一个真实调用 env 的路由，验证 DB URL 解析成功。

### 4.3 nitro.config 的 alpha 字段重组（🔴 高）

`handlers[]`（两条 legacy 路由）、`cloudflare.{deployConfig,nodeCompat,wrangler}`、`rollupConfig.external` 都是 alpha 形态配置。260610 对配置 schema 可能收敛、移动或改名。`handlers[]` 与 `legacy-dispatch` 路由强耦合，若被 beta 移出则 `/app/**`、`/callComponent/**` 两条 legacy 链路直接失效。

- 前置动作：对照官方 config 文档核对三项字段在 260610 中的归属与写法，提前写好迁移 patch。
